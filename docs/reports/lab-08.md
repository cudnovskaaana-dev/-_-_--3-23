# Отчёт по лабораторной работе №8

**Тема:** REST API заявок на повреждение кабеля  
**Студент:** Чудновская Я.В., ТРИС-3-23

## Цель

Реализовать согласованные с ЛР2 операции создания, чтения, назначения исполнителя и смены статуса.

## Реализованные маршруты

| Метод и путь | Назначение |
|---|---|
| `POST /api/cable-tickets` | Создать заявку, ответ 201 |
| `GET /api/cable-tickets` | Получить список, включая пустой список |
| `GET /api/cable-tickets/{id}` | Получить заявку или 404 |
| `PATCH /api/cable-tickets/{id}/assignee` | Назначить электромонтёра |
| `PATCH /api/cable-tickets/{id}/status` | Сменить статус или вернуть 409 при конфликте процесса |

Входной DTO проверяет длину заголовка, описания и положительный `siteId`. Участок и электромонтёр должны существовать. Создана Postman-коллекция `docs/api-collection/cable-tickets.postman_collection.json`.

## Проверка

Проверено через `curl`: создание — 201; короткий заголовок — 400; неизвестный id — 404; пустой список и фильтр без совпадений — `200 []`; перевод неназначенной заявки в работу — 409; назначение, перевод в `InProgress` и закрытие — 200. При отключении тестовой БД API ответил 500 с безопасным телом `{"error":"Внутренняя ошибка сервера."}`; сервер записал stack trace и путь запроса в лог. После восстановления БД API продолжил работу.

## Вывод

HTTP-слой разделён на контроллер, DTO и сервис. Статус 400 относится к неверным входным данным, 404 — к отсутствующей записи, 409 — к запрещённому переходу состояния.

# Отчёт по лабораторной работе №10

**Тема:** Связь Web API с PostgreSQL через EF Core  
**Студент:** Чудновская Я.В., ТРИС-3-23

## Цель

Заменить память процесса постоянным хранилищем PostgreSQL, не меняя REST-контракт ЛР8.

## Что подготовлено

- Добавлены `AppDbContext`, сущности и PostgreSQL-провайдер EF Core.
- Сервис выполняет создание, чтение, назначение и смену статуса через контекст базы данных.
- Строку подключения можно переопределить через конфигурацию `ConnectionStrings:Default`; значение в репозитории является только локальным шаблоном и должно быть заменено через User Secrets или переменную окружения.
- В репозитории сохранена миграция `InitialCreate`; её применение проверено на PostgreSQL 18.6.

## Проверка

Миграция `InitialCreate` применена к PostgreSQL 18.6. Через API создана заявка `id=6`, номер `КБ-106`; после назначения и перехода в `Closed` API был перезапущен. GET до и после рестарта вернул ту же заявку `id=6`, статус `Closed`, исполнителя `2`.

## Вывод

EF Core управляет постоянным хранилищем, а REST-контракт остался прежним. Рестарт-тест подтвердил, что запись переживает перезапуск сервера.

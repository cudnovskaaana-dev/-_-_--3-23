# Отчёт по лабораторной работе №6

**Тема:** Vue-клиент программного интерфейса (API) для заявок на повреждение кабеля  
**Студент:** Чудновская Я.В., ТРИС-3-23

## Цель

Перевести список и создание заявок на асинхронные функции API, сохранив текущие экраны Vue. До появления реального сервера используется mock с таким же интерфейсом функций.

## Что подготовлено

- `frontend/src/api/tickets.js` содержит `getTickets` и `createTicket`.
- `frontend/src/api/mockTickets.js` имитирует задержку и ответы 201, 400 и 500.
- Список показывает загрузку, пустое состояние, таблицу или сообщение об ошибке.
- Форма отправляет данные асинхронно, различает ошибки валидации, сервера и связи, блокирует повторную отправку.
- Номер и идентификатор для новой заявки создаются источником данных и приходят в теле ответа.
- Базовый адрес задаётся через `VITE_API_BASE_URL`; коммитится только пример `.env.example`.
- Для демонстрации ответа 500 mock поддерживает `VITE_MOCK_FORCE_500=true` (после изменения `.env` Vite нужно перезапустить).
- Для демонстрации отдельной ветки HTTP 400 предусмотрен `VITE_MOCK_FORCE_400=true`; обычная форма валидирует поля до запроса, поэтому этот флаг позволяет показать обработку ответа API без изменения формы.

## Проверка по требованиям методички

| Сценарий | Результат проверки |
|---|---|---|
| Успешное создание | Browser UI: строка `КБ-103` с темой «Тестовая заявка из браузера» появилась в таблице после отправки формы |
| Ответ 400 | При `VITE_MOCK_FORCE_400=true` UI показал «Проверьте поля заявки», оставив введённые значения |
| Ответ 500 | При `VITE_MOCK_FORCE_500=true` UI показал «Сервер сломался. Попробуйте позже.» |
| Нет связи | При `VITE_USE_MOCK=false` и адресе `127.0.0.1:59999` UI показал «Нет связи. Проверьте адрес API и доступность сервера.» |

Состояния проверены в браузере. Mock выполняется внутри Vue-приложения и не создаёт HTTP-запросов, поэтому Network для этих сценариев пуст; методичка допускает для такого mock фиксацию состояния экрана/консоли и объяснение, где появится HTTP-запрос после подключения backend.

## Вывод

Клиент отделён от источника данных функциями API, что позволит заменить mock реальным сервером. Успешный сценарий и три вида отказа проверены в браузере. Для mock нет сетевого запроса; при подключении backend он будет виден в Network.

## Лабораторная работа 5. Vue: форма и список в памяти

В этой работе форма создания заявки была связана с общим массивом данных. Теперь кнопка «Создать» реально добавляет новую строку в таблицу.

### Что реализовано:
- **Добавление заявки:** при отправке формы данные попадают в общий `items` (файл `src/ticketsStore.js`).
- **Автоматический номер:** новые заявки получают уникальный `id` и номер (например, `КБ-103`), статус по умолчанию — `New`.
- **Клиентская валидация:** форма проверяет, что тема от 5 до 80 символов, участок больше 0, а описание от 10 до 500 символов. При ошибке под полем появляется красный текст, и заявка не сохраняется.
- **Без перезагрузки:** используется `@submit.prevent`, поэтому нажатие Enter или кнопки «Создать» не обновляет страницу.
- **Переход на список:** после успешного создания форма очищается, а пользователь переходит на главную страницу (`/`), где сразу видит новую строку.

### Ожидаемое поведение (F5):
Так как сервер и база данных на этом этапе ещё не подключены, данные хранятся только в оперативной памяти браузера. Если нажать **F5** (обновить страницу), только что добавленные заявки исчезнут. Это нормально и ожидаемо для текущего этапа обучения (база данных появится в ЛР10).

## Лабораторная работа 6. Vue-клиент API

В `frontend/src/api/` находятся интерфейс клиента и mock. Для локального запуска выполните:

```bash
cd frontend
npm ci
npm run dev
```

По умолчанию используется mock. Для подключения backend задайте `VITE_USE_MOCK=false` в `frontend/.env` и перезапустите Vite.

## Лабораторные работы 7–10. ASP.NET Core и PostgreSQL

- API: `http://localhost:5000`
- Swagger: `http://localhost:5000/swagger`
- Проверка процесса: `http://localhost:5000/health` (не проверяет создание заявки)
- Информация о приложении: `http://localhost:5000/info`

После установки PostgreSQL выполните из папки `backend`:

```bash
dotnet restore
dotnet tool restore
dotnet user-secrets set "ConnectionStrings:Default" "Host=localhost;Port=5432;Database=ris_cable;Username=postgres;Password=YOUR_PASSWORD"
dotnet ef database update
psql -d ris_cable -f ../db/seed.sql
dotnet run
```

Пароль задаётся локально и в репозиторий не помещается. В репозитории уже есть миграция `InitialCreate`; создавать её заново не нужно. SQL-схема, тестовые данные и запросы находятся в `db/`.

Postman-коллекция: [cable-tickets.postman_collection.json](docs/api-collection/cable-tickets.postman_collection.json).
